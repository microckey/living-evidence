# Codex review of the implementation's agent-visible tool surface

> Generated 2026-08-30 via `codex exec` (read-only) against a runtime dump of the
> three pages' tool surfaces (scratchpad review-packet.json — 57KB, repo access
> forbidden to cap token use). Adjudication: docs/CODEX-FIX-DIRECTIVE.md.

Verdict: The surface has a strong orientation-first concept, and the dumped packet itself is valid JSON; its Unicode, newlines, arrays, and `null` values are serialization-safe. It is not yet judge-ready, however. Several sentences materially overstate the statistics, the workspace exposes under-specified schemas, and the Atlas offers actions whose IDs, state effects, or ledger entries cannot be discovered. In its current form, a capable browser agent could confidently repeat conclusions the tools do not establish.

## Findings

- [must-fix] **All pages — `list_claims` / `evaluate_claim`:** `supported` and `challenged` look like truth judgments, but they only report whether an authored predicate matched. Add: “A verdict reports whether the claim’s authored statistical rule matched the current records. It is not an independent judgment of truth, causality, study validity, model choice, or bias.” Prefer `rule_passed`, `rule_failed`, and `rule_requires_qualification`, or return `verdict_scope: "authored statistical rule only"`.

- [must-fix] **Exemplar/workspace — `get_document_overview`; Atlas — `atlas_overview`:** “Never recompute or estimate these numbers yourself” undermines the advertised cross-examination. Replace it with: “Use tool results when reporting page state. Independent calculations are welcome as checks, but label them external and do not silently substitute them for the page’s result.” Scope the validation claim too: “The named fixtures/specifications matched a documented `metafor` version and tolerance; this checks numerical reproduction, not the data or model assumptions.” Ideally return the version, calls, reference values, and tolerance.

- [must-fix] **Workspace — `get_document_overview`, `set_hypothesis`, `get_studies`, `propose_study`, `subgroup_analysis`, `meta_regression`:** The page presents itself as a general workspace but is fixed to the Pygmalion SMD schema—weeks of prior contact, tester blinding, and test setting. Either generalize it or rename it “Living Evidence Workspace — teacher-expectancy/IQ SMD template.” Add: “Changing the hypothesis wording does not change the fixed estimand, effect measure, moderator fields, or supported analyses.”

- [must-fix] **Exemplar — `list_claims`, claim `c-textbook`:** A positive pooled SMD with `p < .05` does not establish that children became generally “smarter.” Keep the provocative sentence as the claim being examined, but replace its rule with: “This narrow check passes iff the REML pooled SMD for measured IQ is positive and its two-sided test of zero has p < .05. Passing does not establish generalized intelligence, uniform benefit, or transportability beyond these experiments.”

- [must-fix] **Exemplar — `list_claims`, claim `c-overall`:** `p ≥ .05` plus a point estimate below `|0.2|` does not establish a small true effect. Replace the statement with: “The REML point estimate is below the conventional |SMD| = 0.2 heuristic, and its two-sided test against zero is not significant at α=.05.” Add: “This is not an equivalence finding; 0.2 is a generic heuristic, not a domain-defined SESOI.” If “the effect is small” is intended, require a predeclared equivalence margin and equivalence test.

- [must-fix] **Exemplar — claim `c-moderator`; exemplar/workspace — `meta_regression`:** “Explains essentially all” and “share of heterogeneity explained” overstate a study-level observational meta-regression. Replace the claim with: “Under the authored model `x=min(weeks,3)`, weeks are negatively associated with effect size and estimated residual REML τ² is at least 90% lower than in the intercept-only fit.” Describe `R2_percent` as a boundary-clipped proportional reduction in estimated τ², with no uncertainty interval and no causal meaning.

- [must-fix] **Exemplar — claim `c-moderator` default verdict:** A significant positive slope falls into the default branch and is falsely described as “moderator not significant.” Add a branch for `p < .05` and `b >= 0`: “The slope is statistically significant but nonnegative, contrary to the claimed negative association.” The remaining default should say: “The required negative association was not detected.”

- [must-fix] **Exemplar — claim `c-window`:** Significance inside a post-hoc subgroup does not demonstrate effect modification. Replace the statement with: “In the post-hoc ≤1-week subset, the subgroup REML estimate is positive and its two-sided test against zero has p < .05.” Every verdict should add: “This is a within-subgroup result; it does not establish a difference from the >1-week subgroup. Use the between-group test for that question.”

- [must-fix] **Exemplar/workspace — `leave_one_out`; exemplar claim `c-robust`:** No significance flip does not show that no study “drives these conclusions.” Replace the claim with: “Omitting one study at a time does not change whether the overall REML mean has p < .05.” Replace the tool’s conclusion with: “Reports estimate changes and p<.05-status flips; it does not establish stability of effect magnitude, moderators, heterogeneity, bias diagnostics, or every document conclusion.”

- [must-fix] **Exemplar/workspace — `funnel_check`; exemplar claim `c-bias`:** Egger’s test concerns funnel asymmetry/small-study effects, not publication bias specifically; a nonsignificant result is not evidence of absence. Rename it “Small-study asymmetry check” and use: “Render a funnel plot and run the specified Egger regression. Asymmetry can have causes other than publication bias, and failure to reject symmetry—especially with k=19—does not establish absence of bias.” Replace the claim with: “Egger’s regression did not detect small-study asymmetry at the prespecified α=.10 threshold.” At α=.10, `p < .10` must fail that rule; do not retain the inconsistent `.05–.10` “nuanced” branch unless it is explicitly a separate strength-of-evidence label.

- [must-fix] **Exemplar/workspace — `cumulative_meta`:** “How the pooled estimate evolved as evidence accumulated” implies a historical evidence-availability reconstruction. Replace it with: “Retrospective cumulative meta-analysis ordered by publication year. It shows prefixes of the current corpus; it does not reconstruct which evidence was actually available or discoverable at each historical date.”

- [must-fix] **Exemplar/workspace — `run_meta_analysis`; Atlas — `synthesize`:** FE is a common-effect model, not a τ² estimator. Use: “REML or DL random-effects, or FE common-effect.” For FE, return `tau2: null` or explicitly state `tau2: 0` is imposed by the model rather than estimated. State the p-value’s null, sidedness, and test.

- [must-fix] **Exemplar/workspace — `propose_study`:** The schema accepts negative variance, negative weeks, fractional years/sample sizes, blank provenance, and an effect with no direction convention. Require `year: integer`, `vi: {exclusiveMinimum:0}`, `weeks: {minimum:0}`, positive-integer sample sizes, and trimmed nonempty strings. Define the exact SMD variant and direction, e.g. “positive means higher measured IQ under induced expectancy than control.” Rename `setting` to something unambiguous such as `iq_test_administration`, and rename `n1i`/`n2i` to group-specific fields.

- [must-fix] **Exemplar/workspace — `propose_study`:** A single quote is insufficient when `yi` or `vi` is derived from several reported values. Add structured provenance such as `source_locator`, `quoted_source_values`, and `derivation`, or explicitly require a directly reported effect/variance. Always return `possible_duplicate_of: string|null`, and identify `record_hash` as non-cryptographic if applicable.

- [must-fix] **Workspace — `add_claim`:** `test` is merely `{type:"object"}`, so `{}` passes visible schema validation despite the promise that its shape is validated. Supply a closed nested schema requiring `analysis`, typed `args`/`focus`, nonempty `verdicts`, typed conditions, the operator and verdict enums, and exactly one default branch. Also expose valid analyses and addressable result paths through `get_claim_rule_schema` or copyable templates; otherwise an agent must guess hidden path names such as `f.estimate`.

- [must-fix] **Workspace — `set_hypothesis`:** Enforce the advertised limit with `minLength:1` and `maxLength:500`, plus a trimmed-nonblank handler check. State that invalid text is rejected rather than silently truncated.

- [must-fix] **Workspace — `propose_study` / `get_document_overview`:** The approval handoff is a five-minute dead end. Add: “This creates only a pending card and does not change `k`. There is no agent approval tool: ask the human to click Approve, then call `get_document_overview` again. At least two approved records are required for synthesis.” Present this as an ordered workflow and identify the workspace as an authoring demo, not the fastest cross-examination page.

- [must-fix] **Workspace — `export_document`:** Returning the entire self-contained HTML in `{filename,bytes,html}` risks response truncation and consumes the agent’s context after initiating a download. Default to `{filename,bytes,download_started,content_digest}`. If programmatic HTML is necessary, gate it behind `include_html:false` or a separate chunked/resource-return tool.

- [must-fix] **Atlas — `atlas_overview`, all action tools:** “READ-ONLY” conflicts with tools marked non-read-only that change visible state and append ledger entries. Replace it with: “EVIDENCE-IMMUTABLE: no tool adds, removes, or persists records, edges, or claims. `evaluate_claim`, `synthesize`, `get_study_brief`, and `focus_node` change ephemeral page/UI state and append session-ledger entries.” Also state whether page state is isolated from the exemplar/workspace; “no backend” currently leaves cross-page propagation ambiguous.

- [must-fix] **Atlas — `synthesize` + `evaluate_claim`:** Their state relationship is unspecified. Add either: “`synthesize` changes only the displayed synthesis; `evaluate_claim` always reruns the claim’s stored AST and full-record arguments,” or describe the alternative behavior equally explicitly. Without this, an agent may exclude a study and falsely assume the next verdict uses that exclusion.

- [must-fix] **Atlas — `focus_node`, `synthesize`, `get_cell`:** Most usable IDs are undiscoverable. The surface exposes ID forms but not the 19 record IDs or construct/document/moderator IDs. Add `list_records`/`list_nodes`, returning at least `{record_id,node_id,label,yi,vi,weeks,...}` and references for all focusable node types.

- [must-fix] **Atlas — identifier arguments:** `focus_node` uses `rec:s10`, `synthesize.exclude` uses bare `s04`, `evaluate_claim` uses bare `c-window`, and focused claims use `claim:c-window`. Standardize IDs or return both explicit fields (`record_id` plus `node_id`, `claim_id` plus `node_id`). For the single-cell `get_cell`, remove `cell_id` or constrain it with `const:"cell:teacher-expectancy-iq"`.

- [must-fix] **Atlas — `get_study_brief`:** Its description invites any gap ID, although two of three gaps have `brief_available:false`. Say: “Compile a gap whose `get_gaps` result has `brief_available:true`; currently only `gap:coverage-weeks`.” Constrain the schema accordingly, or return `{available:false,reason}` rather than a generic error. Rename it “Prospective study-design brief” to avoid confusion with a summary of an existing study.

- [must-fix] **Atlas — tools described as ledgered:** There is no Atlas `get_audit_log`. Add the same read tool used on the other pages, or stop implying that the agent can inspect the ledger.

- [must-fix] **Atlas — `get_gaps`, coverage gap:** The raw 8–16 band is empty, but it is not a uniquely unsupported region of the capped model: every week ≥3 maps to `x=3`, already represented by records at 3, 5, 7, 17, 19, 21, and 24 weeks. Replace the statement with: “Observed weeks are 0, 1, 2, 3, 5, 7, 17, 19, 21, and 24; none fall from 8 through 16. Under `x=min(weeks,3)`, the fitted line crosses zero near 2.59 weeks and predicts approximately SMD −0.064 for every raw value ≥3.”

- [must-fix] **Atlas — `get_gaps.rank​ed_by`; `get_study_brief.rationale`:** “The model is most confident exactly where it has never been tested” is false; no uncertainty or confidence ranking is returned. Replace it with: “Raw-moderator coverage gap; no confidence or priority ranking is inferred. Because all weeks ≥3 map to `x=3`, this band has no distinct fitted prediction under the current model.” Replace “model criticism, not effect-hunting” with: “A preregistered study in this band would add raw-week coverage and could assess the authored cap against prespecified uncapped or nonlinear alternatives while also estimating the effect in that band.”

- [must-fix] **Atlas — `get_gaps.note`:** “Every number … computed, not authored” ignores the authored gap definitions and cap-at-3 model. Replace it with: “Observed values, estimates, and derived gap bounds are computed from the current records under authored gap definitions and model specifications; changing either can change the result.”

- [must-fix] **Atlas — `get_gaps`, replication gap:** The schema has no preregistration field, so `count_with_prereg:0` converts an unmeasured property into measured absence. Return `count_with_prereg:null`, `assessment_status:"not_collected"`, and retitle it “Preregistration linkage unknown.” Use: “Preregistration linkage was not assessed for these records; the schema cannot represent it. No inference about the existence of preregistered replications is available.”

- [must-fix] **Atlas — `get_gaps`, verification gap:** “Every record sits below R2” conflicts with “record rungs are unassigned,” and R2 is undefined to the agent. Replace it with: “No shipped record has a per-record source quote, approval event, or data manifest. Exact ladder rungs are unassigned; if R2 requires a manifest, no record can currently be certified as R2 or higher.” Define R2 if the label remains.

- [must-fix] **Atlas — `get_study_brief.design_implication`:** “A superiority test is the wrong shape” is unjustified before the estimand and SESOI are chosen. Replace it with: “The Atlas cannot choose the test. If the question is practical equivalence, define δ and plan an equivalence analysis; if the question is any positive effect, superiority answers that different question.”

- [must-fix] **Atlas — `get_study_brief.current_estimates`:** Neither estimate is a “selection-biased optimistic bound”; the dump establishes neither the direction of selection bias nor a mathematical bound. Use “Descriptive estimate from the current corpus; corpus selection is unknown, so this is neither a bound nor a justified planning value,” and “Post-hoc subgroup estimate from the same corpus; not independent validation or a justified planning value.”

- [must-fix] **Atlas — `get_study_brief.unresolved_inputs`:** Replace “a school-year follow-up loses pupils” with “may lose pupils.” Replace “only criticism … if registered” with: “Preregistration strengthens a confirmatory model test by separating the prediction and analysis from observed results; an unregistered result remains informative but is exploratory.” Say missing inputs are “not present in this Atlas/corpus,” not that they do not exist.

- [must-fix] **Atlas — `get_cell`:** `relation_type:"causal"` reads as an achieved validity judgment despite acknowledged gaps in clustering, attrition, measurement, and record verification. Replace it with: “causal estimand—contrast of assigned expectancy induction versus no induction; causal validity depends on the original randomization, clustering, attrition, and outcome-measurement assumptions.” Define the exact SMD variant and positive direction here too.

- [nice-to-have] **All pages — result contracts:** Add output schemas. Standardize on fields such as `ci95:{lower,upper}`, `i2_percent`, `tau_squared`, `q:{statistic,df,p_value}`, `p_test`, `effect_direction`, and explicit nullable/error states. Current `ci:[lower,upper]`, `I2`, machine-check paths like `ci_lower`, and page-specific shapes require unnecessary inference.

- [nice-to-have] **Atlas — `get_cell.records_by_weeks_band`:** Avoid human-formatted dynamic keys such as `"≤ 1 week"`. Return stable records such as `{band_id:"le_1",lower:null,upper:1,count:8}`.

- [nice-to-have] **Exemplar/workspace — `subgroup_analysis`:** “Numeric fields need `split_at`” contradicts the stated default, and categorical calls can carry meaningless thresholds. Use: “For `weeks`, omit `split_at` to use 1 or provide another threshold; `split_at` is rejected for `setting` and `tester`.” Encode this with `if/then/else` or `oneOf`.

- [nice-to-have] **Exemplar/workspace — `meta_regression`:** Restrict `cap` to appropriate moderators, require it to be positive, and return a structured error for constant moderators or insufficient records. Applying `cap=3` to `year` would otherwise create a degenerate predictor.

- [nice-to-have] **All action tools:** Make each description self-contained about side effects: “Changes visible page state and appends one session-ledger entry; it does not alter approved evidence.” State whether `run_meta_analysis` changes `current_overall_fit` or merely renders an additional figure.

- [nice-to-have] **Exemplar/workspace — `get_audit_log`:** Call FNV-1a a “non-cryptographic checksum for detecting accidental payload changes, not authentication or tamper evidence.” Clarify that “append-only” is session-local and add pagination such as `after_run`/`limit`.

- [nice-to-have] **Exemplar — `get_document_overview`:** The mandatory first call duplicates every complete claim AST from `list_claims`. Return only `{id,statement,status,stale}` summaries and say: “Call `list_claims` for authored rules; call `evaluate_claim` directly with an ID above.”
